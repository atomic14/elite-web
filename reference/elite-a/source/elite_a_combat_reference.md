# Elite-A combat and ship-table reference

This pack separates three things that the original game stores differently: **NPC blueprint health and weapons**, **flyable-player-ship characteristics**, and **the per-system blueprint-set/role assignments**. The exact S.A–S.W variants are retained in the JSON; the tables below summarise them for a clean recreation.

## Recommended clean combat rules

```text
NPC defence       = maxEnergy & 7
Player laser hit  = (fittedLaserByte & 0x7f) >> 1
Constrictor hit   = playerLaserHit >> 1
Damage to NPC     = max(0, hit - NPC defence)
NPC laser hit     = NPC laserPower << 2  // clean recreation
Damage to player  = max(0, NPC laser hit - playerShip.perHitShieldArmour)
Destroy           = currentEnergy <= 0
Hits to destroy   = ceil(maxEnergy / damagePerHit), when damagePerHit > 0
```

The released game computes a firing NPC laser hit as `weaponByte >> 1` after first confirming that the laser-power bits are non-zero. Because the low bits hold missile count, that makes missiles alter laser damage by up to 3 points. The clean rule above uses `laserPower << 2`, which preserves the intended scale while removing that encoding side-effect. Both values remain in the JSON tables.

For the recreation, keep regeneration time-based: `regenAccumulator += deltaTime * regenPerSecond`. Do **not** add one point every eighth 60 fps frame unless you deliberately want 7.5 energy/second. A sensible starting point is `1.0 energy/second` for ordinary AI ships, `0` for stations, missiles, cargo and rocks, then tune from playtesting. This real-time rate is a recreation choice because the original ties regeneration to its variable-duration main loop.

The original player has fixed 255-point forward shield, 255-point aft shield and 255-point energy-bank capacities. The flyable ship table’s “shields” value is an extra **per-hit armour subtraction**, not the size of those shield bars.
